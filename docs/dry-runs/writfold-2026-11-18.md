# Dry run: writfold, 18 November 2026 (milestone M0b)

**Kind:** observational calibration run. Not a benchmark, not an adoption.
Run on a throwaway local clone of writfold (`ff7ce76`, "Prepare
v0.6.0-dev.8: version"); no writfold files were changed, no writfold gates
run, nothing committed there.

**Command** (tiers assumed, not declared by writfold):

```console
cargo tauten check --format json \
  --assume-tier writfold-core=kernel --assume-tier writfold-domain=core \
  --assume-tier writfold-sources=core --assume-tier tuft=core --assume-tier '*=edge'
```

## What the run changed in tauten

The dry run exposed four defects in tauten itself. All are fixed, and each
has a regression test or fixture:

1. **Crates linted under several tiers.** `cargo clippy` applies its flags to
   every workspace crate it compiles, so dependencies were also linted under
   their dependents' tiers. The fix is one `cargo check` with `cargo-tauten`
   as `RUSTC_WORKSPACE_WRAPPER`, applying each crate's own tier. The fixture
   test now asserts one tier per crate.
2. **Dependents silently skipped.** Deny-level lint errors fail rustc, so
   crates depending on a crate with violations were never checked; the first
   run had no results for app, runtime or tui. Lints now compile at warn
   level and the profile assigns severity. Covered by fixture
   `rej-dependent`.
3. **Order-dependent findings.** Cargo stops scheduling after the first
   failure; the fix is `--keep-going`.
4. **Test noise.** 696 of 745 panic-in-`Result`-fn findings and 713 of 1,069
   ambient-filesystem findings were in tests. Rules gained `in_tests`, and
   test targets get a relaxed profile. Explicit `let _ =` discards are allowed
   in tests (TAU-E003), while silent drops are not. Covered by fixture
   `rej-test-hygiene`.

## Observations

- **The tier guess for writfold-kb was wrong.** Run as `core`, it produced
  1,063 ambient-authority findings: the knowledge base performs file and git
  IO directly. Either it is an edge crate, or its decision logic should move
  into a core crate. That is a real design question surfaced by the tiers,
  not lint noise.
- **The kernel conflicts with its proofs.** writfold-core is proved with
  Aeneas, which treats overflow and out-of-bounds as failure and proves they
  do not occur. tauten still reports 231 arithmetic and indexing findings
  there. The proof tier should subsume N001/P003 for functions with a proved
  no-failure theorem, rather than ask for rewrites. Recorded as a design item
  for M3.
- **Worth looking at in writfold:**
  - 48 `map_err(|_| …)` that discard the original error;
  - 32 ignored results in writfold-runtime;
  - 23 `#[allow]` without a reason.
- **Adoption cost** for writfold under the full profile is roughly 750 error
  sites outside documentation. That argues for the planned ratchet (stage 2):
  record a baseline and block only new violations.
