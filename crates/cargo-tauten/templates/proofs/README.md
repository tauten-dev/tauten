# Proofs for `{{CRATE}}`

Lean 4 theorems about the Charon/Aeneas translation of `{{CRATE_DIR}}`,
set up by `cargo tauten init --proofs {{CRATE}}` (tauten's proof tier; the
same pins and gate steps as tauten's own proofs). `TRUST.md` lists what is
trusted rather than proved.

## Files

| File | Role |
|---|---|
| `claims.toml` | What is proved: per Rust function, its theorems and the mutants that must break them; the gate command |
| `claims.json` | Generated by `cargo tauten proofs`: one outcome per claim, with a fingerprint of the sources the gate saw. Commit it; it is the badge data, and `cargo tauten check` reads it |
| `Extracted/` | The committed translation (`sh proofs/refresh.sh`); the gate refuses drift |
| `Proofs.lean`, `Proofs/` | Your theorems |
| `Audit.lean` | Axiom audit (only `propext`, `Classical.choice`, `Quot.sound`) and the list of total theorems |
| `gate.py` | The gate, inside the image: tools, extract, drift, build, audit, mutants |
| `run.sh`, `compose.yaml`, `container.sh` | Run the gate in the pinned image from the host |
| `extract.sh`, `refresh.sh` | Translate a crate; regenerate `Extracted/` |

## Workflow

1. Pull the image (linux/amd64, about 20 GB):
   `docker pull ghcr.io/tauten-dev/proofs-toolchain:lean-4.35.0-aeneas-c5eb4a2-charon-8cae8fd`.
2. `cargo fmt`, then `sh proofs/refresh.sh` and commit `proofs/Extracted/`.
3. Write theorems in `Proofs/`, stated over the extracted definitions
   (`{{CRATE_SNAKE}}.<function>`). Import each file from `Proofs.lean`.
4. Add a `[[claim]]` per function and a `[[mutant]]` per claim to
   `claims.toml`. A mutant is a textual change to the Rust source (it must
   match exactly once) that breaks at least one of the claim's theorems.
5. `cargo tauten proofs`. It prints one JSON line per claim:
   `{"crate": …, "function": …, "theorems": […], "mutants": […], "outcome": …}`
   with `outcome` one of `proved`, `drift`, `build-failed`, `audit-failed`,
   `mutant-survived`, `tool-missing`, and writes `claims.json`. Without
   Docker or the image every claim is `tool-missing`; nothing passes
   without the gate.

## Assumptions about the outside world

A theorem about code that talks to the outside world (a filesystem, a
clock, a hash function) usually needs a premise the code cannot prove. Do
not make it a Lean `axiom`. Name it:

1. Define it once in `proofs/assumptions.toml` (`id`, `statement`, `scope`,
   `tested_by`).
2. Tag the Lean proposition with the same ID and take it as a hypothesis:

       @[tauten_assumption "FS.rename-atomic"]
       def RenameAtomic (fs : FsModel) : Prop := ...

       theorem publish_old_or_new (fs : FsModel) (h : RenameAtomic fs) : ...

3. In the claim (`version = 2`), list it under `assumes` and name a
   `witness`: a theorem with no such hypothesis whose conclusion is the
   assumptions (a conjunction or an existential of them, for example of an
   in-memory model). It shows they can hold together, so the theorems are
   not vacuous. Optional `necessity` theorems show an assumption is needed.

The audit derives which assumptions each theorem's hypotheses use; a claim
whose `assumes` is not exactly that list, or whose witness does not
establish it, is `audit-failed`. A claim with assumptions is recorded as
`proved-under`, never `proved`, and never subsumes a finding. Adding an
assumption to a recorded claim needs an `[[amend]]` entry (TAU-R002).

## Subsuming arithmetic and indexing lints

In a `kernel` crate, a claim may name a `total` theorem: one of the shape
`∀ args, f args ⦃ r => … ⦄` with no hypotheses (the audit checks the shape).
It states that `f` returns for every input without a panic, an overflow or
an out-of-bounds access. With `subsumes = ["TAU-N001", "TAU-P003"]`,
`cargo tauten check` then reports those findings inside `f` as
"subsumed by proof <theorem>", not as errors, as long as `claims.json`
records `proved` for the current source. Any edit to the crate or to
`proofs/` makes the record stale and the findings come back until the gate
is run again.

## Writing kernel code that translates

Owned data, no nested borrows; no derives reached from translated
functions (compare enums with `match`); no integer casts; explicit `while`
loops over `get` (no iterator chains or closures); one loop per function
when it returns early; flat matches; a `match` on `xs.get(i)` directly in
a loop body may crash Aeneas (move it into a helper); no parameter named
like its module; `Option::is_none` and similar are better written as a
`match`.
